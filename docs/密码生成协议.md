# 花钥确定性密码生成协议 FK-DP1

> 更新时间：2026-07-28
> 更新概要：冻结 FK-DP1 的输入规范化、密钥派生、字符表、输出规则与兼容性承诺。

## 1. 协议地位

FK-DP1 是花钥首个正式确定性密码生成协议。稳定版发布后，任何可能改变既有输入输出结果的规则都不得修改。

允许继续更新界面、自动填充、同步、本地存储和性能实现；但相同的主密码、身份密语、完整区分代号、密码类型与密码长度必须永久生成逐字符完全相同的密码。

若未来必须采用新算法，只能新增协议版本。旧协议必须继续可用，且不得静默迁移历史条目。

## 2. 输入

FK-DP1 使用五项输入：

1. 主密码；
2. 身份密语；
3. 完整区分代号；
4. 密码类型；
5. 密码长度。

主密码按用户输入的完整 Unicode 字符串编码，不修改大小写、空格、标点或字符宽度。

身份密语仅执行 Unicode NFC 规范化，之后按 UTF-8 编码。不得修改大小写、删除空格、转换简繁体或转换全角半角。

首次创建身份密语时，客户端必须拒绝首尾空白并要求用户完整重输确认，不能静默裁剪。该限制用于避免用户无意中创建多年后难以复现的输入；FK-DP1 生成函数本身仍按完整输入只执行 NFC，以兼容已存在的确定性结果。

完整区分代号按以下固定顺序规范化：

1. 移除首尾空白；
2. 执行 Unicode NFC 规范化；
3. 仅将 ASCII `A-Z` 转换为 `a-z`。

内部空格、中文、数字和符号保持原样。因此 `GitHub`、`Github`、`github` 和 `GITHUB` 等价，但 `QQ邮箱` 与 `QQ 邮箱` 不等价。

## 3. 固定配置

密码类型仅允许：

- `alphanumeric`：字母和数字；
- `with_symbols`：字母、数字和特殊字符。

密码长度仅允许：

- 8 位；
- 16 位，默认；
- 32 位。

8 位仅用于不支持更长密码的旧系统。24 位及其他任意长度不属于 FK-DP1。

FK-DP1 字符表及顺序永久固定：

```text
字母：abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ
数字：0123456789
字母数字：abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789
特殊字符：!@#$%^&*()-_=+[]{}|;:,.<>?
```

`with_symbols` 的完整字符表为“字母数字”后直接拼接“特殊字符”。

## 4. 密钥派生与密码生成

生成根密钥：

```text
rootKey = PBKDF2-HMAC-SHA256(
  password = UTF8(masterPassword),
  salt = UTF8(NFC(identitySecret)),
  iterations = 600000,
  outputLength = 256 bits
)
```

确定性原始字节：

```text
raw = HMAC-SHA256(rootKey, UTF8(normalizedCodename))
mix = HMAC-SHA256(rootKey, UTF8(normalizedCodename + "_mix"))
```

初始密码的第 `i` 位由 `raw[i mod 32] mod 字符表长度` 选择。随后使用 `mix` 确定性保证字符类型：

- 第 1 位替换为字母；
- 在第 2 位到末位之间确定一个位置并替换为数字；
- `with_symbols` 模式再确定一个不与前两者冲突的位置并替换为特殊字符。

因此 `alphanumeric` 输出必定同时包含字母和数字；`with_symbols` 输出必定同时包含字母、数字和特殊字符。

## 5. 实现约束

- 核心库与 Android 原生自动填充必须通过同一组固定测试向量。
- 各端不得自行增加字符、改变字符顺序或调整输出位置规则。
- 无效密码类型和非 8/16/32 长度必须明确报错，不能静默降级。
- 界面文案、语言和内部枚举显示不得参与密码生成。
- 域名、URL、Android 包名、标签、文件夹和设备 ID 不得参与密码生成。
- 本地数据库与 WebDAV 仅保存便利元数据，不得成为重建密码的必要输入。
- 已初始化设备若找到同一区分代号的本地条目，必须优先使用条目保存的密码类型和长度；只有空设备或不存在该条目时，才使用界面当前选择或默认配置。

身份密语如何在已初始化设备上加密包装、如何由系统安全能力快速解锁，不属于 FK-DP1 输出协议，但属于花钥的发布安全边界。正式格式使用“主密码 + 随机设备包装盐”独立派生 AES-256-GCM 包装密钥；本地不得持久化身份密语明文。设备包装方案可以新增版本，但解包后交给 FK-DP1 的身份密语字符串必须保持一致。

主密码和身份密语都是不可变的确定性根输入。普通设置与恢复流程不得修改它们；恢复码只能恢复原主密码。完整设计见 `docs/plans/2026-07-28-identity-wrapping-immutable-credentials-design.md`。

## 6. 发布冻结检查

每次修改核心密码代码、Android 自动填充或构建工具时，都必须运行固定测试向量。任意向量输出变化均视为协议破坏，必须阻止发布。

固定向量至少覆盖：

- 中文区分代号；
- ASCII 大小写等价；
- 中英文混合区分代号；
- 两种密码类型；
- 8、16、32 三种长度；
- 字母与数字必含；
- 特殊字符模式必含特殊字符；
- 无效类型和长度拒绝。
