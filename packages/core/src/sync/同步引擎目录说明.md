# 同步引擎目录说明

更新时间：2026-05-17
更新概要：补充同步锁二次读回竞态保护说明。

## 目录作用

WebDAV / 通用存储后端同步引擎目录，负责多端增量同步、同步锁控制、冲突解决与快照压缩。

## 文件列表

| 文件 | 作用 |
| ---- | ---- |
| `backend.ts` | 同步后端接口定义：统一抽象目录初始化、文件读写、删除与 oplog 列表能力。 |
| `changelog.ts` | 变更日志与 oplog 序列化：负责本地 ChangeLog 与远端操作日志之间的转换。 |
| `engine.ts` | 同步主逻辑：协调推送、拉取、同步锁、快照压缩，并在成功后持久化最近一次成功同步时间。 |
| `webdav.ts` | WebDAV 客户端封装：适配远端目录、文件读写与 oplog 列举，兼容坚果云等服务。 |

## 技术说明

- 冲突解决策略为 Last-Write-Wins，以 `updatedAt` 时间戳为准。
- 远端目录结构为 `/FlowerKey/oplog/{deviceId}_{timestamp}.enc`，超过阈值后压缩为 `vault.enc`。
- 所有 oplog 与快照内容均通过 AES-256-GCM 加密，`sync.lock` 仅保存非敏感锁信息。
- `engine.ts` 在一次同步成功结束后会写入本地 `syncState.lastSyncTime`，供各端设置页展示“最近一次成功同步”。
- 书签加密状态不一致时会累计 `encryptMismatchCount`，用于向 UI 返回可见提示。
- 同步锁获取使用写入后读回与随机等待后的二次读回；若二次读回发现锁已被其他设备覆盖，当前设备只放弃本次同步，不删除对方锁。

## 使用示例

```ts
const engine = new SyncEngine(config, dbKey, deviceId);
const result = await engine.sync();
// result: { pushed, pulled, encryptMismatch? }
```

## 扩展方式

1. 若新增同步后端，优先实现 `backend.ts` 定义的接口，再注入 `SyncEngine`。
2. 若新增同步状态持久化字段，应统一写入本地配置，避免只保留在内存中。
3. 若扩展冲突解决策略，需要同步检查 `applyOp()`、快照恢复与 UI 提示是否一致。

## 注意事项

- `lastSyncTime` 表示“最近一次成功完成同步流程”的时间，不等于远端一定产生新数据。
- 坚果云存在 API 频率限制，避免在短时间内高频重复触发同步。
- 修改远端目录结构或文件命名规则时，需要同步检查已有设备的兼容性。
- 修改同步锁逻辑时必须覆盖“并发设备覆盖锁后，失败方不得删除胜出方锁”的回归场景。
