# 核心库目录说明

> 更新时间：2026-07-29
> 更新概要：新增 FK-SECRET-1 秘密载荷与 FK-BACKUP-1 加密备份，移除书签创建能力。

## 目录作用

FlowerKey 的核心逻辑库，包含加密、数据层、数据模型，所有端（浏览器插件/桌面/移动）共享此库。

## 文件列表

| 文件 | 作用 |
| ---- | ---- |
| `src/index.ts` | 库入口，导出所有公共 API |
| `src/models.ts` | 数据模型定义（Entry、ChangeLog、UserConfig 等） |
| `src/crypto.ts` | 核心加密库（PBKDF2 密钥派生、HMAC-SHA256 密码生成、AES-256-GCM 加解密） |
| `src/crypto.test.ts` | 加密库单元测试（盐、验证哈希、密码生成、AES、恢复码） |
| `src/direct-password.spec.ts` | 首屏直算与区分代号规范化匹配测试 |
| `src/secret.ts` | FK-SECRET-1 秘密载荷的创建、序列化与严格解析 |
| `src/backup.ts` | FK-BACKUP-1 AES-256-GCM 加密备份封装与旧明文导入兼容 |
| `src/db.ts` | 数据层（基于 Dexie.js 封装 IndexedDB，Entry CRUD + ChangeLog） |
| `src/db.test.ts` | 数据层单元测试（条目加密、CRUD、搜索、配置、旧书签清理） |
| `src/sync/changelog.ts` | 同步 oplog 序列化/反序列化 |
| `src/sync/changelog.test.ts` | oplog 序列化测试 |
| `src/sync/engine.ts` | 增量同步引擎（push/pull、锁、LWW、压缩快照） |
| `src/sync/engine.test.ts` | 同步引擎单元测试（内存后端和本地适配器） |
| `package.json` | 包配置，依赖 dexie、uuid |
| `tsconfig.json` | TypeScript 编译配置，生产构建排除测试文件 |

## 技术说明

- 加密全部基于 Web Crypto API，零外部依赖
- 密钥派生使用 PBKDF2-SHA256（600,000 次迭代）
- FK-DP1 使用“记忆密码 + 身份密语 + 规范化区分代号”确定性生成密码
- 区分代号执行 NFC、移除首尾空白并将 ASCII `A-Z` 转小写
- 密码配置冻结为两种字符模式和 8/16/32 三种长度
- 固定测试向量覆盖中文代号、中英文混合代号和 Android 原生实现
- 数据加密使用 AES-256-GCM，格式：`[1B version][12B IV][ciphertext+tag]`
- 密钥分离原则：验证哈希、生成根密钥、数据库密钥、身份包装密钥使用不同盐域
- `masterPasswordData` 只保存版本化身份包装密文，不保存身份密语明文
- 恢复码加密并恢复原主密码，不提供主密码修改能力
- 秘密的标题、内容、账号、标签、文件夹和备注封装进 `FK-SECRET-1`，作为单一 `content` 字段整体加密
- 备份使用当前数据库密钥整体加密为 `FK-BACKUP-1`；旧明文 JSON 只允许导入，不再导出
- 旧书签仅保留本地删除与远端拒收兼容，不提供创建、导入或恢复能力
- 单元测试使用根目录 Vitest 配置，IndexedDB 测试通过 fake-indexeddb 在 Node 环境运行

## 扩展方式

- 新增数据模型：在 `models.ts` 中添加接口定义
- 新增加密功能：在 `crypto.ts` 中添加函数并从 `index.ts` 导出
- 新增数据库表：在 `db.ts` 的 `FlowerKeyDB` 类中添加

## 注意事项

- 所有异步加密操作返回 Promise
- `db.ts` 中的写操作自动记录 ChangeLog（用于增量同步）
- 修改数据库 schema 需要增加 Dexie version 号
- 新增核心逻辑时同步补充对应 `*.test.ts`，生产 `tsc` 构建不会输出测试文件
- FK-DP1 稳定发布后不得修改字符表、规范化、派生参数或输出映射
- 旧 `userSalt` 明文格式属于发布前开发数据，不迁移、不兼容
