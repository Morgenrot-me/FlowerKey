# 状态管理目录说明

## 目录作用

桌面端 Pinia 状态目录，负责连接桌面页面与 core 数据层，管理解锁、条目列表与 WebDAV 同步状态。

## 文件列表

| 文件 | 作用 |
| ---- | ---- |
| `main.ts` | 主状态：管理解锁状态、主密码初始化、运行时数据库密钥，以及锁定态首屏的正式/独立直算流程。 |
| `entries.ts` | 条目状态：负责密码/书签/笔记列表加载、搜索过滤、增删改，并统一按最近使用时间排序。 |
| `sync.ts` | 同步状态：管理 WebDAV 配置、同步过程、本次同步结果，以及持久化的最近一次成功同步时间。 |

## 技术说明

- 桌面端与 extension 共用 `@flowerkey/core` 的 IndexedDB 数据层与 `SyncEngine`。
- `sync.ts` 仅支持 WebDAV，同步后会重新读取本地 `syncState.lastSyncTime`，供设置页展示可验证状态。
- `entries.ts` 依赖 core 数据层的最近使用记录，保证桌面端排序与其他端一致。
- `main.ts` 复用共享直算流程，在锁定态也能完成正式模式校验入库与独立计算模式。

## 使用示例

```ts
import { useSyncStore } from './sync';

const syncStore = useSyncStore();
await syncStore.loadConfig();
await syncStore.sync();
console.log(syncStore.lastResult, syncStore.lastSyncTime);
```

## 扩展方式

1. 新增桌面端状态时，优先放在本目录，避免把页面临时状态误放进共享组件。
2. 若同步流程新增展示信息，先补 `sync.ts`，再同步更新 `SettingsTab.vue`。
3. 若条目字段扩展，需要同步更新 `entries.ts`、页面表单与 core 数据模型。

## 注意事项

- 桌面端同步逻辑不要混入移动端专属的 iCloud 或自动填充判断。
- `lastResult` 仅代表本次运行内最近一次同步结果；跨重启是否真的成功，应以 `lastSyncTime` 为准。
- 修改 store 返回字段后，需同步检查所有页面是否仍能正常响应。
