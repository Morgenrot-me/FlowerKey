# Pinia 状态目录说明

## 目录作用

Pinia 状态管理目录，负责连接共享 UI 组件与 core 数据能力，统一维护解锁状态、条目列表与同步状态。

## 文件列表

| 文件 | 作用 |
| ---- | ---- |
| `main.ts` | 主状态：管理解锁状态、主密码初始化与运行时数据库密钥。 |
| `entries.ts` | 条目状态：负责密码/书签/笔记列表加载、搜索过滤、增删改，并统一按最近使用时间排序。 |
| `sync.ts` | 同步状态：管理 WebDAV 配置、同步中状态、本次同步结果，以及持久化的最近一次成功同步时间。 |

## 技术说明

- 基于 Pinia setup store 写法实现，便于在组件中直接组合使用。
- `sync.ts` 通过 `@flowerkey/core` 中的 `SyncEngine` 发起同步，并在同步完成后重新读取本地 `syncState.lastSyncTime`。
- `entries.ts` 与 core 的 `db.touchLastUsed()` 配合，保证列表排序与最近使用记录一致。
- `main.ts` 提供运行时解锁能力，其余 store 依赖它判断是否允许读写敏感数据。

## 使用示例

```ts
import { useSyncStore } from './sync';

const syncStore = useSyncStore();
await syncStore.loadConfig();
await syncStore.sync();
console.log(syncStore.lastSyncTime);
```

## 扩展方式

1. 新增状态模块时，优先按业务域拆分，避免把无关逻辑堆进同一个 store。
2. 若同步状态新增字段，优先落在 `sync.ts`，并与设置页文案一并更新。
3. 若条目排序或筛选规则变化，需要同步检查 `entries.ts` 与 core 数据层是否一致。
4. 若引入新的安全状态，优先复用 `main.ts` 的解锁状态，不重复维护第二套鉴权标记。

## 注意事项

- `sync.ts` 的 `lastResult` 只代表当前会话最近一次操作结果，跨重启验证应依赖 `lastSyncTime`。
- 任何涉及敏感数据的 store 调用都应先确认已解锁，避免未授权读取。
- 修改 store 对外返回字段后，需要同步检查所有引用组件是否仍匹配。
