# 状态管理目录说明

## 目录作用

移动端 Pinia 状态目录，负责连接移动端页面、SQLite 数据层与平台同步能力，管理解锁、条目、WebDAV / iCloud 同步等状态。

## 文件列表

| 文件 | 作用 |
| ---- | ---- |
| `entries.ts` | 条目状态：负责密码/书签/笔记列表加载、搜索过滤、增删改，并统一按最近使用时间排序。 |
| `icloud.ts` | iCloud 同步后端：封装移动端 iCloud Drive 读写能力，供同步状态调用。 |
| `main.ts` | 主状态：管理解锁状态、主密码初始化与运行时数据库密钥。 |
| `sync.ts` | 同步状态：管理同步模式、WebDAV 配置、全量同步、本次同步结果，以及持久化的最近一次成功同步时间。 |
| `webdav-native.ts` | 原生 WebDAV 后端：适配移动端网络与文件读写能力，供 `SyncEngine` 调用。 |

## 技术说明

- 移动端同步以 `sync.ts` 为统一入口，根据 `syncMode` 在 WebDAV 与 iCloud 之间切换。
- `sync.ts` 在普通同步与全量同步完成后都会重新读取 `syncState.lastSyncTime`，用于设置页展示可验证状态。
- `icloud.ts` 与 `webdav-native.ts` 都实现 core 所需的存储后端接口，最终由 `SyncEngine` 统一编排。
- `entries.ts` 与 SQLite 数据层配合，保证最近使用排序与 desktop / extension 一致。

## 使用示例

```ts
import { useSyncStore } from './sync';

const syncStore = useSyncStore();
await syncStore.loadConfig();
await syncStore.setSyncMode('icloud');
await syncStore.sync();
console.log(syncStore.lastSyncTime);
```

## 扩展方式

1. 若新增同步后端，先在本目录实现后端适配，再接入 `sync.ts` 的模式切换。
2. 若同步状态新增展示字段，需同时更新 `SettingsTab.vue` 的反馈文案。
3. 若平台能力变化，优先放在独立 store 或后端适配文件中，不把原生细节直接写进页面。

## 注意事项

- `lastResult` 只代表当前会话最近一次操作结果，历史成功状态应看 `lastSyncTime`。
- iCloud 与 WebDAV 并非所有设备都支持，新增逻辑时不要假设后端一定存在。
- 修改同步状态结构后，要同步检查 `SettingsTab.vue`、同步说明文案与平台分支逻辑。
