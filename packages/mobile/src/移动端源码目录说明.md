# 移动端源码目录说明

## 目录作用

本目录存放移动端 Vue 应用源码、SQLite 数据适配、全局样式与应用入口，是 Capacitor 移动端前端和原生数据桥接的主要实现区域。

## 文件列表

| 文件 / 目录 | 作用 |
|-------------|------|
| `App.vue` | 移动端应用根组件，负责根据初始化、解锁、重置与自动填充提示状态切换首屏页面。 |
| `main.ts` | Vue 应用入口，初始化 Pinia、挂载根组件，并启动 SQLite 初始化流程。 |
| `style.css` | 移动端全局样式，包含 Tailwind 引入、深色模式基础样式与通用表单类。 |
| `db-sqlite.ts` | SQLite 数据库适配层，负责移动端 Entry CRUD、配置读写、敏感配置加密、变更日志和最近使用时间维护。 |
| `db-sqlite.test.ts` | SQLite 数据库适配层测试，覆盖同步直接写入时保留 `lastUsedAt` 等移动端字段一致性行为。 |
| `assets/` | 移动端静态资源目录，例如图标、图片等构建时资源。 |
| `pages/` | 移动端页面组件目录，包含解锁、设置、密码与加密秘密库等界面。 |
| `stores/` | 移动端 Pinia 状态目录，连接页面、SQLite 数据层与同步后端。 |

## 技术说明

- 移动端使用 Vue 3、TypeScript、Pinia 与 Tailwind CSS。
- 数据层使用 `@capacitor-community/sqlite`，同时需要兼容 Android 原生 AutofillService 对同一数据库的直接读取。
- `db-sqlite.ts` 中影响同步的写操作必须记录 `changelog`，同步专用 `putEntry()` 则不记录日志，避免远端拉取后再次推送。
- 敏感字段加密规则复用 `@flowerkey/core` 的 `encryptEntry()` / `decryptEntry()`，保持多端数据格式一致。
- `lastUsedAt` 是本地最近使用排序字段，不参与冲突解决，但 SQLite 写入和同步落库时必须保留，避免列表排序回退。

## 使用示例

```ts
import { initSQLite, putEntry, getEntriesByType } from './db-sqlite';

await initSQLite();
await putEntry(entryFromSync);
const passwords = await getEntriesByType('password');
```

## 扩展方式

1. 新增数据库字段时，先更新 `CREATE TABLE`、旧库 `ALTER TABLE` 迁移、`putStoredEntry()` 写入列和 Android 原生 SQL 读取逻辑。
2. 新增移动端页面时放入 `pages/`，并在 `App.vue` 或主布局中接入。
3. 新增跨页面状态时放入 `stores/`，优先复用 core 类型，避免页面直接操作原生插件细节。
4. 新增全局样式时优先扩展 `style.css` 中已有通用类，避免页面内重复定义。

## 注意事项

- 修改 `db-sqlite.ts` 后必须同步检查 Android 原生自动填充代码是否依赖同一字段。
- SQLite 同步写入路径和普通用户写入路径行为不同，测试时需要分别覆盖。
- 移动端源码不能直接依赖 core 的 Dexie 单例数据库，浏览器 IndexedDB 与移动端 SQLite 需要保持适配层边界。
- 新增或修改源码文件后，应立即更新本目录说明文档，保持文件职责说明同步。
