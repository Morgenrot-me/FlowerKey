# 脚本目录说明

> 更新时间：2026-07-30
> 更新概要：版本同步增加 Cargo.lock，并补充纯函数回归测试。

## 目录作用

本目录存放项目级自动化脚本，用于版本同步、图标生成、构建产物收集等跨包维护任务。

## 文件列表

| 文件 | 作用 |
|------|------|
| `sync-version.js` | 从根 `package.json` 读取版本号，并同步到各子包、Cargo、Tauri、浏览器插件 manifest 与 Android 版本。 |
| `sync-version-utils.js` | 提供不访问文件系统的 Cargo.lock 精确版本替换函数。 |
| `sync-version-utils.test.ts` | 验证版本同步只修改 FlowerKey 桌面包，不误改第三方 Cargo 依赖。 |
| `collect-release.ps1` | 收集 Android APK、桌面端安装包、浏览器插件 zip 和解压目录到根目录 `release/`。 |
| `gen-icons.ps1` | 从源图生成常规应用图标资源。 |
| `gen-icons-gold.ps1` | 从源图生成金色主题图标资源。 |
| `gen-ico.ps1` | 生成 Windows `.ico` 图标文件。 |

## 技术说明

- `sync-version.js` 是版本号唯一同步入口，根版本修改后应运行 `pnpm version:sync`；桌面端 `Cargo.toml` 和 `Cargo.lock` 必须同步。
- Android `versionCode` 按 `major * 10000 + minor * 100 + patch` 计算，保证版本递增。
- `collect-release.ps1` 会重建根目录 `release/`，执行前应确认已有收集产物可被覆盖。
- PowerShell 脚本主要面向 Windows 本地构建环境。

## 使用示例

```powershell
pnpm version:sync
powershell -File scripts/collect-release.ps1
```

## 扩展方式

1. 新增跨端构建或发布辅助逻辑时，优先放在本目录。
2. 新增脚本后，在本说明文档的文件列表中补充用途、输入和输出。
3. 若脚本会删除或覆盖文件，应在脚本注释和使用说明中明确写出影响范围。

## 注意事项

- 不要在脚本中写入密钥、token 或生产发布凭据。
- 修改版本同步范围时，必须同步检查所有端的构建产物是否读取了对应文件。
- 涉及清理目录的脚本运行前需要确认目标目录，避免误删源码或未备份产物。
